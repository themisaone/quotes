📦 Storage & Performance
Description
Vault path, export embed threshold, and one-time migration of DB attachments to disk.

Set a custom folder for all attachment files (PDFs, videos, large images). Leave empty to use the default attachments/ folder inside the app.
Dropbox / NAS / external drive: copy the attachments/ folder there manually, enter the parent path here, click Verify, then Save Settings.
File references in the database use relative sub-paths, so they work automatically after moving.

Recommended: ON - Resize images to max 1024px before storing (~100-200 KB each).
OFF: Store raw images - large files go to external attachments folder based on threshold below.
⚠️ Turn OFF only for testing or if you need full-resolution images.

Attachments up to this size are embedded as base64 in JSON exports (self-contained backup). Attachments larger than this are kept as file references and listed in a separate big_files.txt report.
1 MB (recommended) — compact exports, only large files need separate backup.
Lower (0.5 MB) — smaller JSON exports, more files need separate backup.
Higher (2–5 MB) — larger JSON exports, fewer files need separate backup.

One-time migration: converts every attachment_full still stored as base64 in the database into a file on the vault disk, updating the DB reference. Thumbnails are not touched — they stay in DB. Safe to re-run: notes already pointing to a file are skipped.
